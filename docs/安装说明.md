# APB v2 安装说明

APB 现在按 DSH profile bundle 交付。包名为 `@deepseek-ai/dsh-apb`，不再使用
自定义 PowerShell 复制脚本，也不直接写入 `$DSH_HOME` 下的插件目录。

## 从当前源码目录安装

在仓库根目录执行：

```powershell
dsh plugin --profile web add .
```

DSH 会自动维护目标 profile 的 `package.json`、依赖目录和
`dsh.profile.bundles`。确认组合层已生效：

```powershell
dsh --profile web --dump-config
```

输出中应包含 `@deepseek-ai/dsh-apb` 和 `apb-mode`。

## 从 tarball 安装

生产交付建议使用已构建的 npm 包或 tarball：

```powershell
pnpm pack --pack-destination <输出目录>
dsh plugin --profile web add <输出目录>\deepseek-ai-dsh-apb-<版本>.tgz
```

每次发布升级都应递增包版本。源码目录安装是 pnpm 的开发链接，适合开发调试；
tarball 或 registry 包适合跨机器交付和卸载验收。

## 升级

使用新的版本包再次执行标准 `add`，或对 registry 依赖执行：

```powershell
dsh plugin --profile web update @deepseek-ai/dsh-apb
```

不要手工复制到 `node_modules`，也不要手工编辑 `dsh.profile.bundles`。

## 卸载

```powershell
dsh plugin --profile web remove @deepseek-ai/dsh-apb
```

DSH 会同步移除 profile 依赖和 bundle 层；不会修改用户自己的
`cordis.patch.yml` 内容。

## Bundle 与 preset

DSH bundle 和 agent preset 是两种不同的机制：

- bundle `@deepseek-ai/dsh-apb` 由 `dsh plugin` 安装、升级、卸载；
- `apb-coding` 是 agent preset，当前仍作为独立 preset 内容维护，后续再按
  `dsh-agent-presets` 的规则处理，不将其伪装成 profile bundle。
