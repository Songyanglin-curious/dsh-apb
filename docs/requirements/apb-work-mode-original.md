我现在需要的工作模式和工作能力如下：
ask 模式 ：用户和AI进行问答式对话 但是此时 只允许Ai有读取的权限
plan 模式：不是凭空生成的而是根据上面的ask对话生成的计划  只允许Ai有读取的权限
build 模式：根据上面的对话或者是plan 执行具体干活  拥有全部权限

---
**该模式不做复杂的长任务的直接完成 而是按照人类的编码思路进行辅助加快**

比如我们实现一个模块人的实现思路是先进行思考讨论确认大致的方向上没有明显的漏洞后
进行代码入口的实现和简单的文件步骤规划
然后是使用todo占位
然后 是一个模块一个模块实现并且进行调试
当整个流程打通后 说明第一遍工作做完了
然后是对代码进行重构
重构也是一步步的重构
比如；第一次就是将零散的变量名称使用对象组织起来
第二步将一部分步骤 拿个方法明组装起来
第三步将剩下的零散步骤都拿方法名组织起来
第四步再逐个对现有的模块进行审核 对于 一个方法干了多件事的或者不太合适的进行细致的拆分，或者对于那种特别多条件进行模式拆分等让其更清晰更模块化更内聚的方向优化
第五步对外层的架构或者说整体架构进行分析将层级划分清楚：比如外层是流程编排层 里面是业务实现层但是业务实现层有编排层的工作就要进行重构

---
总的来说是要符合人的工作方式思考方式渐进式递归的思考深入实现；禁止一次出现一大堆的思考与实现。
